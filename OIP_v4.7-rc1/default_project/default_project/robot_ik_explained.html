1. El Robot: Estructura y Cinematica Directa

1.1 Arquitectura mecanica

El SixAxisRobot es un manipulador antropomorfico de 6 grados de libertad (DOF). Cada grado corresponde a una revolvente (joint) con un eje de rotacion fijo:

JointEjeFuncionRango
J1Y (vertical)Giro de base — selecciona "branche" (izq/der)±180°
J2Z (lateral)Hombro — lleva el brazo arriba/abajo±135°
J3Z (lateral)Codo — dobla el brazo para alcance±160°
J4Y (vertical)Muneca — giro del wrest±180°
J5Z (lateral)Muneca — inclinacion de la herramienta±120°
J6Y (vertical)Giro final — orienta el EOAT (herramienta)±360°

La cadena cinematica es una serie de nodos anidados en Godot:

// Estructura jerarquica (simplificada)
Base ─[J1 rotY]─► Shoulder ─[J2 rotZ]─► Arm1 ─[J3 rotZ]─► Elbow
  ─[J4 rotY]─► Wrist1 ─[J5 rotZ]─► Wrist2 ─[J6 rotY]─► ToolHolder
    ─► VacuumArea (copa) ─► ToolTipMarker (punta exacta)

1.2 Cinematica Directa (FK)

La cinematica directa resuelve: "dado un vector de angulos $\theta = [J_1, J_2, ..., J_6]$, ¿donde esta la punta de la herramienta?"

Matematicamente, cada joint $i$ contribuye con una matriz de rotacion $R_i(\theta_i)$ alrededor de su eje:

$$R_y(\alpha) = \begin{pmatrix} \cos\alpha & 0 & \sin\alpha \\ 0 & 1 & 0 \\ -\sin\alpha & 0 & \cos\alpha \end{pmatrix}, \quad R_z(\alpha) = \begin{pmatrix} \cos\alpha & -\sin\alpha & 0 \\ \sin\alpha & \cos\alpha & 0 \\ 0 & 0 & 1 \end{pmatrix}$$

La posicion del tooltip es:

$$\mathbf{p}_{tip} = R_1 \cdot \left( \mathbf{d}_1 + R_2 \cdot \left( \mathbf{d}_2 + R_3 \cdot \left( \mathbf{d}_3 + ... \right) \right) \right)$$

donde $\mathbf{d}_i$ es el vector de desplazamiento (link length) del segmento $i$. En Godot, esto se calcula automaticamente al componer las transformaciones de la jerarquia de nodos.

En nuestro caso, la FK la resuelve el motor de Godot: robot.get_tool_tip_position() retorna la posicion global del nodo TooltipMarker despues de aplicar todas las rotaciones de la cadena.

1.3 Lo que hace especial a este robot

A diferencia de un robot " ideal" donde los joints y la herramienta estan alineados, nuestro robot tiene un descentramiento critico: la copa (VacuumArea) esta desplazada respecto de los ejes de J4, J5 y J6. Esto significa que mover la muneca (J4/J5) no solo cambia la orientacion sino que tambien desplaza la posicion del tooltip.

Dato clave: Medimos el desplazamiento del tooltip al perturbar cada joint desde una pose base:
J4 ±45° → 19.6 cm J5 ±20° → 9.0 cm J6 ±90° → 0.0 cm
J6 rota exactamente sobre el centro de la copa (eje Z de la herramienta), por eso no afecta la posicion. Pero J4 y J5 mueven la punta centimetros.

2.3 Por que es dificil

La cinematica inversa (IK) resuelve el problema inverso: "dado un punto objetivo $\mathbf{p}^*$ y una orientacion $\mathbf{R}^*$, ¿que angulos $\theta$ logran eso?"

Para un robot de 3 DOF con herramienta alineada, esto seria relativamente simple (geométrico o con CCD). Pero nuestro caso tiene tres complicaciones:

  1. Acoplamiento pos-orien: J4/J5 mueven la posicion 20cm, no solo la orientacion.
  2. Lmites articulares: Cada joint tiene rangos finitos; no todas las configuraciones son validas.
  3. Two ramas: J1 puede ser positivo (~145°) o negativo (~-145°), dando dos "brazos" distintos que llegan al mismo lado.

3. Cinematica Inversa: Los Algoritmos

3.1 CCD (Cyclic Coordinate Descent)

CCD es un algoritmo iterativo que ajusta un joint a la vez, desde la punta hacia la base. Para cada joint $i$:

  1. Calcula el vector del pivot al tooltip: $\mathbf{v} = \mathbf{p}_{tip} - \mathbf{p}_{pivot_i}$
  2. Calcula el vector del pivot al objetivo: $\mathbf{w} = \mathbf{p}^* - \mathbf{p}_{pivot_i}$
  3. Calcula el angulo entre ellos: $\alpha = \arccos\left(\frac{\mathbf{v} \cdot \mathbf{w}}{|\mathbf{v}||\mathbf{w}|}\right)$
  4. Gira el joint $i$ por $\alpha$ (clampeado al paso maximo)

Esta implementado en six_axis_robot.gd:501-522:

// CCD clasico: solo posicion
for j in range(5, -1, -1):
    var axis := pivots[j].global_transform.basis.y  // o .z
    var jacobian := axis.cross(tip - pivot.global_position)
    var dot_val := clampf(proj_tip.dot(proj_target), -1.0, 1.0)
    var angle := acos(dot_val)
    set(JOINT_ANGLE_PROPS[j], clampf(current + rad_to_deg(angle), MIN, MAX))
Pro: Simple, rapido, converge en ~80 iteraciones para posicion pura.
Contra: No maneja orientacion directamente; queda atrapado en minimos locales cuando la herramienta esta descentrada.

3.2 CCD con orientacion (solve_ik_pose)

Extension del CCD que agrega un termino de orientacion al calculo de cada joint. En vez de solo minimizar posicion, minimiza una funcion combinada:

$$\delta_i = \underbrace{\mathbf{J}_i \cdot \mathbf{e}_{pos}}_{\text{posicion}} + k_{rot} \cdot \underbrace{\mathbf{a}_i \cdot \mathbf{e}_{ori}}_{\text{orientacion}}$$

donde:

  • $\mathbf{J}_i = \mathbf{a}_i \times (\mathbf{p}_{tip} - \mathbf{p}_{pivot_i})$ es el Jacobiano geometrico (contribucion del joint $i$ al movimiento de la punta)
  • $\mathbf{e}_{pos} = \mathbf{p}^* - \mathbf{p}_{tip}$ es el error de posicion
  • $\mathbf{e}_{ori}$ es el error de orientacion en formato eje-angulo (quaternion)
  • $k_{rot} = 0.4$ es el peso de orientacion

Implementado en six_axis_robot.gd:529-569:

var jacobian := axis.cross(tip - pivot.global_position)
var delta := jacobian.dot(e_dir) + k_rotation * axis.dot(w_err)
delta = clampf(delta, -max_joint_step, max_joint_step)
Este algoritmo funciona bien para 6 de 8 puntos — pero las columnas 4 (Point15 y Point19) quedan atrapadas en minimos locales. ¿Por que? Porque los seeds iniciales caen en la "cuena" incorrecta y CCD no puede escapar.

3.3 Levenberg-Marquardt (LM)

LM es un algoritmo de optimizacion no-lineal que combina lo mejor del gradiente descendente (稳健 pero lento) con Gauss-Newton (rápido cerca del minimo). Resuelve un sistema de ecuaciones en cada paso:

$$(J^T J + \mu I) \Delta\theta = -J^T \mathbf{r}$$

donde:

  • $J$ es la matriz Jacobiana $m \times n$ (6 residuos × 6 joints)
  • $\mathbf{r}$ es el vector de residuos (error de posicion + orientacion escalada)
  • $\mu$ es el parametro de damping (adaptativo)
  • $\Delta\theta$ es el paso a tomar en el espacio de joints

El damping $\mu$ es la clave:

  • $\mu$ grande → paso conservador (gradiente descendente) →稳健 pero lento
  • $\mu$ pequeño → paso agresivo (Gauss-Newton) → rapido pero puede divergir
  • Si el paso mejora el costo: aceptar y reducir $\mu$ (×0.4)
  • Si el paso empeora: rechazar y aumentar $\mu$ (×4)

Implementado en test_solve_grid_v47.gd:274-336:

func _lm_pose(start, target, target_tool) -> Array:
    var cur := _clamp_angles(start)
    var mu := 1.0e-3
    for _iter in range(400):
        // Jacobiano numerico 6×6
        for jj in range(6):
            pert[jj] += 0.05  // paso de 0.05 grados
            jac[r][jj] = (res_pert[r] - res_cur[r]) / 0.05
        // Resolver (J^T J + μ I) d = -J^T r
        var delta := _gauss_solve(n, rhs)
        // Aceptar/rechazar paso
        if t_cost < cur_cost:
            mu = maxf(mu * 0.4, 1.0e-9)  // aceptar
        else:
            mu *= 4.0  // rechazar, mas damping

4. El Descubrimiento: Acoplamiento Copa-Muneca

4.1 El problema enigmatico

Despues de implementar el solver de posicion y resolver correctamente los 8 puntos en posicion (error < 0.02 mm), descubrimos que la orientacion no se podia resolver por separado. El solver de muneca (J4-J6) movia la orientacion a Euler (0°, 90°, 0°) exacto, pero el tooltip se desplazaba 10+ cm.

Para investigar, escribimos un probe de sensibilidad (test_probe_wrist_sensitivity.gd):

4.3 Que significa esto

La copa (VacuumArea) no esta centrada en los ejes de J4/J5. Fisicamente, la copa esta desplazada hacia un lado del eje de la muneca. Cuando J4 gira 45°, la copa "barril" un arco de ~20cm. Esto crea un acoplamiento critico:

Regla descubierta: En un robot con herramienta descentrada, orientacion y posicion NO son problemas independientes. Resolver una etapa y luego la otra conduce a infinitos ciclos o minimos locales. Hay que resolverlas simultaneamente.

Esto explica por que el solver CCD (que ajusta joints secuencialmente) fallaba para las celdas externas: la orientacion correcta requeria movimientos de J4/J5 que desplazaban la posicion, y al re-fijar la posicion se perdia la orientacion.

5. La Solucion: LM de Pose Completa

5.1 Formulacion del residuo

El solver LM optimiza un vector de 6 residuos: 3 de posicion + 3 de orientacion (escalada):

$$\mathbf{r}(\theta) = \begin{pmatrix} p^*_x - p_x(\theta) \\ p^*_y - p_y(\theta) \\ p^*_z - p_z(\theta) \\ \lambda_o \cdot e_{ori,x} \\ \lambda_o \cdot e_{ori,y} \\ \lambda_o \cdot e_{ori,z} \end{pmatrix}$$

donde $\lambda_o = 0.18$ es el peso de orientacion y $\mathbf{e}_{ori}$ es el vector de error angular en radianes (calculado via cuaternion).

5.2 Jacobiano numerico

El Jacobiano se calcula por diferencias finitas: para cada joint $j$, perturbarlo 0.05° y medir el cambio en cada residuo:

$$J_{ij} = \frac{r_i(\theta + \delta_j \hat{e}_j) - r_i(\theta)}{\delta_j}$$

Esto crea una matriz 6×6 que describe "como afecta cada joint a cada componente del error". El paso de 0.05° es suficientemente pequeno para la precisión pero suficientemente grande para evitar errores de redondeo.

5.3 La ecuacion normal

En cada iteracion, se resuelve el sistema:

$$(J^T J + \mu I) \Delta\theta = -J^T \mathbf{r}$$

Esto se resuelve con eliminacion gaussiana con pivoteo parcial (_gauss_solve). La matriz $J^T J$ es 6×6 y simetrica, asi que solo calculamos la triangular superior:

for r in range(6):
    for c in range(r, 6):  // triangular superior
        var sm := 0.0
        for k in range(6):
            sm += jac[k][r] * jac[k][c]
        n[r][c] = sm; n[c][r] = sm  // simetrica
    n[r][r] += mu  // damping

5.4 Restarts globales

Cuando las semillas del problema (valores de la escena + soluciones vecinas + variantes sinteticas) no convergen a la tolerancia final, el solver ejecuta 60 restarts aleatorios con semilla fija (reproducible). Cada restart prueba un punto aleatorio uniforme en todo el espacio articular:

var rng := RandomNumberGenerator.new()
rng.seed = 20260826  // determinista
for _try in range(60):
    var j := [rng.randf_range(JMIN[0], JMAX[0]),
              rng.randf_range(JMIN[1], JMAX[1]), ...]
    var res := _lm_pose(j, target, target_tool)
    if cpos < 0.0008 and cori < 0.02: return res
Los restarts funcionan porque CCD se queda en una "cuenca de atraccion" local, pero LM con damping puede navegar entre cuencas. Con 60 semillas aleatorias, la probabilidad de encontrar la cuenca correcta es alta.

5.5 Pipeline completo

Fase A: Semillas — escena actual + soluciones vecinas + variantes sinteticas de muneca + extrapolacion de columna 4
Fase B: LM de pose completa (400 iter max) —早cada semilla. Si converge a pos < 0.8mm y ori < 0.02° → retorno inmediato
Fase C: Restarts globales (60 intentos, punto aleatorio uniforme) — mismo LM pero con semillas completamente nuevas
Post: _solve_wrist (Jacobian de orientacion, 240 iter) — pulido fino de Euler → resultado final

9.2 Solver LM completo

func _lm_pose(start, target, target_tool) -> Array:
    var cur := _clamp_angles(start)
    var mu := 1.0e-3
    for _iter in range(400):
        if cur_cost < 1.0e-13: break

        // 1. Jacobiano numerico 6×6
        for jj in range(6):
            pert[jj] += 0.05
            for r in range(6):
                jac[r][jj] = (pert_res[r] - cur_res[r]) / 0.05

        // 2. Ecuacion normal: (J^T J + μI) d = -J^T r
        var n := _build_normal_matrix(jac, mu)
        var rhs := _build_rhs(jac, cur_res)
        var delta := _gauss_solve(n, rhs)

        // 3. Probar paso (clamp ±6°)
        trial[jj] = clamp(cur[jj] + clamp(delta[jj], -6.0, 6.0), MIN, MAX)

        // 4. Aceptar/rechazar
        if t_cost < cur_cost:
            cur = trial; mu *= 0.4   // avanzar, reducir damping
        else:
            mu *= 4.0                 // rechazar, aumentar damping
    return [cur]

9.3 Eliminacion gaussiana

func _gauss_solve(m: Array, rhs: Array) -> Array:
    // Copia la matriz + columna de augmented
    // Pivoteo parcial: busca el mayor |a[col][col]|
    // Forward elimination
    for col in range(nn):
        // swap fila col con fila de mayor pivote
        for i in range(col+1, nn):
            var f := a[i][col] / a[col][col]
            for j in range(col, nn+1):
                a[i][j] -= f * a[col][j]
    // Back substitution
    for i in range(nn-1, -1, -1):
        x[i] = a[i][nn]
        for j in range(i+1, nn):
            x[i] -= a[i][j] * x[j]
        x[i] /= a[i][i]
